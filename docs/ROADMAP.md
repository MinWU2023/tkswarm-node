# 实施路线

## Phase 1：基础管理 MVP（当前）

- 数据库基础模型
- 账号、代理、分组、任务、设置
- Dashboard 与 WebSocket 基础设施
- 本地运行和错误处理

## Phase 2：浏览器适配层

建立统一接口：

```text
BrowserProvider
├─ BitBrowserProvider
├─ AdsPowerProvider
├─ VmLoginProvider
└─ PlaywrightProvider
```

能力：创建/打开/关闭环境、设置代理、查询状态、获得 CDP 地址。优先接入一个实际使用的浏览器供应商。

## Phase 3：账号会话

- 二维码或人工辅助登录
- 登录状态检查
- Cookie/Storage 加密保存
- 单账号及批量操作
- 审计日志和操作限流

## Phase 4：视频发布

- 素材库
- 账号与素材分配
- 调度器、重试、幂等
- 自动化发布执行器
- 结果截图与失败原因

## Phase 5：消息中心

- 会话/好友模型
- 消息同步适配器
- 发送队列和速率限制
- 翻译适配器
- 模板与可选 AI 回复

## Phase 6：生产化

- 用户认证和 RBAC
- 敏感字段加密
- 备份/恢复
- 任务工作进程隔离
- 安装器、自动升级、监控

## 原则

- 独立实现，不复制商业授权或绕过许可。
- 自动化只用于合法控制的账号，并遵守平台规则。
- 平台自动化模块与 CRUD 管理模块隔离，便于持续适配。
